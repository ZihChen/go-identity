## 🚨 當前關鍵安全風險

### 🔴 Critical - 立即修復需求

#### 1. API Key明文儲存 - 🚨 **最高優先級**
- **狀態**: 🔴 **未改善** - 與前次稽核相同
- **位置**: 
  - `internal/infrastructure/models/merchant.go:15`
  - `internal/infrastructure/models/player.go:15`
  - `internal/domain/entity/merchant.go:31,49,111`
- **風險分析**: 
  - API Keys以明文形式存儲在資料庫
  - 一旦資料庫洩漏，所有API Keys直接暴露
  - 無法提供額外的安全保護層
- **影響評估**: **極高** - 可導致整個系統安全性崩潰
- **修復建議**:
  ```go
  // 建議實作
  type Merchant struct {
      // 儲存bcrypt雜湊值而非明文
      APIKeyHash string `gorm:"uniqueIndex;size:255;not null"`
      // 保留原欄位進行遷移過渡
      APIKey string `gorm:"size:255"`
  }
  ```

#### 2. 認證中間件未整合 - 🔴 **關鍵缺失**
- **狀態**: 🔴 **新發現Critical問題**
- **分析**: 雖然實作了完善的`auth_middleware.go`，但未實際部署使用
- **問題**:
  - API端點缺乏實際的身份驗證保護
  - 中間件配置中使用硬編碼API Keys映射
  - 未與merchant repository進行資料庫驗證整合
- **風險**: 所有API端點實際上處於無保護狀態
- **修復要求**:
  - 整合middleware與merchant repository
  - 實作動態API Key驗證
  - 在所有API路由中啟用認證保護

### 🟠 High - 短期修復需求

#### 1. 輸入驗證不足 - 🟠 **新發現High風險**
- **位置**: `internal/adapter/inbound/handler/api/http_handler.go`
- **問題分析**:
  - 大多數API端點只進行基本參數檢查
  - 缺乏完整的資料格式驗證
  - 未實作請求大小限制
  - 缺乏SQL注入防護機制
- **風險實例**:
  ```go
  // 現況：僅基本檢查
  if globalID == "" {
      c.JSON(http.StatusBadRequest, gin.H{"error": "Global merchant ID is required"})
      return
  }
  
  // 建議：完整驗證
  if err := validateGlobalID(globalID); err != nil {
      c.JSON(http.StatusBadRequest, gin.H{"error": "Invalid global ID format", "details": err.Error()})
      return
  }
  ```
- **修復建議**:
  - 實作DTO層級的驗證規則
  - 新增請求參數白名單驗證
  - 實作輸入清理和轉義機制

#### 2. 錯誤處理標準化 - 🟠 **中等風險**
- **問題**: 錯誤回應格式基本統一但缺乏結構化
- **影響**: 客戶端難以程式化處理不同類型錯誤
- **修復需求**: 建立標準化錯誤碼和分級系統

### 🟡 Medium - 中期改善項目

#### 1. 監控系統缺失 - 🟡 **運維風險**
- **現況**: 僅有基本健康檢查端點 (`/health`)
- **缺失項目**:
  - Prometheus metrics收集
  - 分散式追蹤系統
  - 業務指標監控
  - 實時告警機制
- **影響**: 生產環境問題難以及時發現和診斷

#### 2. 日誌安全風險 - 🟡 **新發現**
- **位置**: `internal/infrastructure/utils/helper.go:33-40`
- **問題**: 使用`fmt.Printf`輸出快取錯誤，可能洩漏敏感資訊
- **風險代碼**:
  ```go
  fmt.Printf("Cache data format error for %s key %s, continuing with database query\n", entityName, cacheKey)
  ```
- **修復建議**: 使用結構化日誌系統並實作敏感資料遮蔽
