# 優化玩家資料同步效能

## 問題背景
服務在上線到正式生產環境的時候，營運高峰期DB的CPU耗能達到100%，以至於拖垮大部分的query效能

## 監控指標
| 項目                  | 數值 |
|----------------------|------|
| Query                | `insert into players(account, api_key, created_at, deleted_at, email, global_player_id, last_active_at, …)` |
| % of runtime         | 36.00% |
| Count                | 11,254 |
| Total time (s)       | 153 |
| p50 latency (ms)     | 12 |
| p99 latency (ms)     | 39 |
| Rows read / returned | 0 |
| Rows read            | 0 |


## 優化目標
在不提升DB硬體資源的前提下，優化query，減少頻繁及不必要的DB I/O操作

## 優化方向

1. 將創建好的PlayerEntity放入channel
2. 另起一個異步的goroutine從channel裡取得資料
3. 當資料到達500筆時做批次寫入或是3到5秒的時間內固定從channel裡取資料做一次批次寫入
