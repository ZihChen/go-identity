# Asynq錯誤事件收集與Redis清理系統 (極簡版)

**版本**: v2.0 (最終實現版)  
**日期**: 2025-11-14  
**狀態**: 已完成並部署

## 概述

本文檔記錄了Fat-Identity-Cat專案中Asynq錯誤事件收集流程的極簡實現，專注於兩個核心功能：
1. 當任務進入ErrorHandler時，將失敗事件錯誤訊息寫入DB做永久性儲存
2. 同時移除Redis上該任務的相關資料

**設計原則**: 極簡、直接、無排程依賴

## 核心功能

### 🎯 **ErrorHandler觸發機制**
```
任務執行失敗 → ErrorHandler → [DB儲存 + Redis清理] (同步執行)
```

### ✅ **已實現功能**
1. **錯誤事件持久化** - 失敗任務詳細信息存儲至MySQL
2. **即時Redis清理** - 立即清理失敗任務的Redis數據
3. **智能TaskID生成** - 多層級fallback機制確保唯一識別
4. **Clean Architecture合規** - 符合專案六角型架構
5. **OpenTelemetry集成** - 完整的分佈式追蹤支持

    }

    return u.failedTaskEventRepo.Create(ctx, failedEvent)

### 5. Redis清理服務 (極簡版)

```go
// internal/infrastructure/cache/redis/cleanup_service.go
type TaskCleanupService struct {
    manager *Manager
    logger  infrastructure.Logger
    tracing infrastructure.TracingService
}

func (c *TaskCleanupService) CleanupTaskData(ctx context.Context, taskID string) error {
    client, err := c.manager.GetClient()
    if err != nil {
        return fmt.Errorf("get redis client: %w", err)
    }

    // 需要清理的Redis key patterns（基於taskID）
    keysToDelete := []string{
        fmt.Sprintf("asynq:default:t:%s", taskID),           // 任務hash
        fmt.Sprintf("asynq:default:failed:%s", taskID),      // 失敗任務
        fmt.Sprintf("asynq:default:dead:%s", taskID),        // 死信任務
        fmt.Sprintf("asynq:default:archived:%s", taskID),    // 歸檔任務
    }

    // 使用pipeline批量刪除
    pipeline := client.Pipeline()
    for _, key := range keysToDelete {
        pipeline.Del(ctx, key)
    }

    _, err = pipeline.Exec(ctx)
    return err
}
```

### 6. 核心集成：ErrorHandler (最終版)

```go
// internal/infrastructure/queue/queue.go
func NewWorkerServer(
    cfg *config.Config,
    logger infrastructure.Logger,
    failedTaskUseCase inbound.FailedTaskEventUseCase,
    redisManager *redisCache.Manager,
    tracing infrastructure.TracingService,
) (*asynq.Server, error) {
    
    // 創建任務清理服務
    taskCleanupService := redisCache.NewTaskCleanupService(redisManager, logger, tracing)

    server := asynq.NewServer(redisOpt, asynq.Config{
        ErrorHandler: asynq.ErrorHandlerFunc(
            func(ctx context.Context, task *asynq.Task, err error) {
                taskID := "unknown"
                
                // 智能TaskID獲取 (多層級fallback)
                if w := task.ResultWriter(); w != nil {
                    taskID = w.TaskID()
                } else if taskID == "unknown" || taskID == "" {
                    taskID = generateTaskIDFromPayload(task.Type(), task.Payload())
                }

                // 異步處理：存儲錯誤事件到DB + 清理Redis任務數據
                go func() {
                    bgCtx, cancel := context.WithTimeout(context.Background(), 15*time.Second)
                    defer cancel()

                    // 1. 記錄失敗任務事件到資料庫
                    redisKey := fmt.Sprintf("asynq:default:t:%s", taskID)
                    if createErr := failedTaskUseCase.CreateFailedTaskEventWithRedisInfo(
                        bgCtx, taskID, task.Type(), "default",
                        string(task.Payload()), err.Error(), redisKey, "failed", 0,
                    ); createErr != nil {
                        logger.ErrorLog("Failed to record failed task event", ...)
                    }

                    // 2. 清理Redis上的任務數據
                    if cleanupErr := taskCleanupService.CleanupTaskData(bgCtx, taskID); cleanupErr != nil {
                        logger.ErrorLog("Failed to cleanup Redis task data", ...)
                    }
                }()
            },
        ),
    })
    
    return server, nil
}

// generateTaskIDFromPayload 智能TaskID生成
func generateTaskIDFromPayload(taskType string, payload []byte) string {
    // 嘗試從JSON payload中提取事件ID
    var jsonData map[string]interface{}
    if err := json.Unmarshal(payload, &jsonData); err == nil {
        idFields := []string{"id", "event_id", "task_id", "messageId", "ID", "global_id"}
        for _, field := range idFields {
            if id, exists := jsonData[field]; exists {
                if idStr, ok := id.(string); ok && idStr != "" {
                    return idStr
                }
            }
        }
    }
    
    // 生成基於payload內容的唯一標識符
    hash := md5.Sum(payload)
    hashStr := hex.EncodeToString(hash[:])
    timestamp := time.Now().Unix()
    return fmt.Sprintf("%s_%d_%s", taskType, timestamp, hashStr[:12])
}
```

## 主要特性

### ✅ **極簡設計**
- **單一觸發點**: 只在ErrorHandler中處理，無額外排程
- **兩個核心功能**: DB儲存 + Redis清理
- **一次處理**: 失敗時同時完成兩項任務

### ✅ **智能TaskID處理**
- **優先方法**: 從ResultWriter獲取
- **備選方法**: 從payload提取事件ID
- **保底方法**: 生成唯一hash標識符
- **格式**: `taskType_timestamp_hash` (例如: `merchant:sync_1763088301_dca7f5ebd249`)

### ✅ **精確Redis清理**
清理目標key patterns:
- `asynq:default:t:{taskID}` - 任務hash
- `asynq:default:failed:{taskID}` - 失敗任務
- `asynq:default:dead:{taskID}` - 死信任務
- `asynq:default:archived:{taskID}` - 歸檔任務

### ✅ **異步處理**
- 不阻塞ErrorHandler執行
- 15秒超時保護
- 完整的錯誤處理和日誌記錄
