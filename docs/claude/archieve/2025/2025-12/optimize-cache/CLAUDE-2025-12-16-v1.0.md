## 技術架構

### 泛型快取輔助函式
**位置**: `internal/infrastructure/cache/helper.go`

```go
func QueryWithCache[T any](
    ctx context.Context,
    cache infrastructure.CacheManager,
    cacheKey string,
    ttl time.Duration,
    entityName string,
    dbQuery func(ctx context.Context) (T, error)
) (T, error)
```

**核心功能**:
- **類型安全**: 泛型函式具備編譯時期類型檢查，消除執行時期類型斷言錯誤
- **Cache-Aside 模式**: 標準的 cache-aside 實作，支援 TTL
- **資料庫回退**: 快取未命中時自動回退到資料庫查詢
- **錯誤處理**: 具備上下文感知日誌的全面錯誤處理
- **TTL 管理**: 針對不同實體類型的可配置 TTL（預設：5 分鐘）

### CacheManager 介面增強
**位置**: `internal/domain/ports/outbound/infrastructure/cache.go`

```go
type CacheManager interface {
```

**增強功能**:
- **Del 方法**: 新增實體更新的快取失效支援

- **介面合規性**: 透過適當抽象維護 Clean Architecture 邊界

## Redis Pipeline 最佳化

### 批次快取失效
**位置**: `internal/application/usecase/player/batch_processor.go`

```go
func (p *PlayerBatchProcessor) batchInvalidateCache(ctx context.Context, players []*entity.Player) {
    pipeline, err := p.cache.Pipeline()
    if err != nil {
        // 回退到個別快取操作
        p.fallbackInvalidateCache(ctx, players)
        return
    }
    
    for _, player := range players {
        cacheKey := fmt.Sprintf(consts.RedisPlayerGlobalIDKey, player.GetGlobalPlayerID())
        pipeline.Del(ctx, cacheKey)
    }
    
    _, err = pipeline.Exec(ctx)  // 單次 Redis 往返
}
```

**效能優勢**:
- **I/O 減少**: 多個快取失效操作的單次 Redis 往返
- **批次效率**: 每次 pipeline 操作最多 500 個快取失效
- **回退安全性**: Pipeline 失敗時全面回退到個別操作
- **高吞吐量支援**: 針對玩家批次同步場景最佳化

## 架構品質成就

### Clean Architecture 合規性
```
UseCase 層級（商業邏輯 + 快取整合）
    ↓ 依賴注入
CacheManager 介面（領域埠）
    ↓ 實作  
Redis Manager（基礎架構）
```

**架構優勢**:
- **依賴反轉**: UseCase 層級依賴 CacheManager 介面，非具體實作
- **介面隔離**: 商業邏輯與基礎架構關切的清晰分離
- **單一責任**: 快取邏輯隔離在專用輔助函式中
- **開放封閉原則**: 易於擴展快取功能而不修改既有程式碼

### 類型安全與泛型
- **編譯時期驗證**: 泛型函式防止執行時期類型斷言錯誤
- **程式碼重用性**: 單一 `QueryWithCache[T any]()` 函式服務所有實體類型
- **可維護性**: 類型安全快取操作減少偵錯複雜度
- **效能**: 泛型實作無執行時期類型檢查開銷
